# 访谈音频校注 Web 应用

面向口述史 / 访谈录音的**转写片段校注**工具：导入带时间戳的转写稿，在时间轴上
拖选区间，为区间标注**说话人、主题、备注**，导出校注 JSON。支持两位校注者离线
各自编辑同一份基准稿后，进行**三方合并（three-way merge）**——互不重叠的改动
自动合并，重叠改动保留双方版本并要求逐项裁决，裁决结果可继续导出或写回项目。
也支持**规则批量标注**：按说话人、关键词 / 正则、最短持续时间批量命中片段，
在时间轴上预览拟生成区间，确认后批量写入；再次运行同一规则只更新其自身结果，
手工标注永不覆盖，每次应用均可一键撤销。项目内还提供**校注质检工作台**：在
指定时间区间上建立扫描线，检测校注越界、校注之间的时间重叠与说话人不一致，
按严重级别筛选、点击问题定位时间轴，可修复的越界项支持一键裁剪后保存，
质检结果可导出 JSON。项目内另设**校注覆盖盲区工作台**：基于已保存的转写
片段与校注，按说话人统计实际发言时长、已覆盖时长与覆盖率并列出未覆盖的
发言区间（同名校注才可覆盖、越界与重叠均不重复计时），可按说话人筛选，
点击区间返回编辑页定位时间轴。项目编辑页内置**引语检索**：输入短语（及可选说话人），
可命中跨越多个时间相接、同说话人片段的引语，逐字标出原文命中字符，点击结果
定位时间轴。项目编辑页还内置**发言时长**面板：按当前转写片段的半开时间区间
统计每位说话人的独讲时长、同讲时长，列出多人同讲区间与全体同时发言区间，
点击区间即可定位时间轴，未保存的片段编辑也会立即刷新统计。项目编辑页还
内置**接话关系**面板：先合并同一说话人相交或相接的片段，再按全部起止
边界划分独讲 / 同讲 / 静默区间，对时间上相邻且说话人不同的独讲区间判定
**普通接话**（中间仅有不超过可设阈值的静默）与**插话**（中间仅有这两人
同时发言），按有向说话人对列出两类次数与逐次时间，点击记录即可定位
时间轴。项目内另设**说话人归一工作台**：从已保存的转写片段、校注与规则的精确说话人条件汇总
现有名称，配置多条「旧名 → 目标名」映射（链式映射自动归并到最终名称，
空目标与循环映射会被阻止），确认前预览每个名称的最终去向及受影响的
片段 / 校注 / 规则数量，确认后在一次事务中改写三处说话人字段（记录 ID
与其他内容不变，失败不留部分修改），随后返回编辑页，引语检索与发言时长
立即使用新名称。项目编辑页还提供**摘录包**：输入多段起止时间（顺序不限、
允许重叠），预览时自动合并相交或首尾相接的区间，只收录完整落在合并区间内
的转写片段，跨界片段整段列为排除项（绝不截取片段全文充作摘录），校注按边界
裁剪、跨越多个不相连区间时拆成多条并保留原校注 ID 作为来源标识；确认后下载
只读 JSON，原项目不会被修改。项目编辑页还提供**公开版转写**：输入多条敏感词
与需匿名的说话人，即可基于**当前已保存**的转写生成可对外公开的版本——敏感词
匹配忽略空白、可跨时间相接且说话人相同的片段（遇空隙、重叠或换人即断开），
命中的非空白字符按原字符位置替换为方块（重叠命中只遮盖一次，原空白、片段
ID、起止时间与分段全部保留），选中的说话人替换为预览与下载一致的匿名编号；
确认后下载只含片段的 JSON，原项目不会被修改。项目编辑页还提供
**转写错词批量校正**：填写多组「错词 → 正词」，基于**已保存**的转写逐片段
预览命中与校正后文本（同一位置优先最长错词、逐片段仅扫描原文一次、替换出
的文字不继续匹配；空错词与重复错词会被提示修正）；确认时校验预览对应的
转写版本与词表，期间转写被编辑或重新导入会被拒绝并要求重新预览，校验通过
后在一次事务中保存改动的片段文本，片段 ID、时间、说话人及全部校注保持不变。
项目读取结果附带**稳定的文档版本**（整份文档的内容指纹），编辑页保存时
携带读取时的版本，后端在同一写入锁内比对：若期间另一页面已保存（如确认
了错词校正），旧页面的整份保存被拒绝（409、任何字段都不写入），编辑页
保留未保存草稿并提示重新加载，重新加载后才能再次保存——同一项目在两个
页面打开时不会互相覆盖。保存请求进行中仍可继续编辑：保存结果只确认该次
请求提交的快照，期间若又有改动，当前草稿与「未保存」提示保留并自动采用
响应中的新版本供再次保存，不会把后续改动误报为已保存。

- 前端：React 18 + Vite（纯 CSS，无 UI 框架依赖）
- 后端：FastAPI（Python 3.11）
- 数据库：本地 SQLite（单文件，挂载于 `./data`）
- 部署：单镜像、单容器，Docker 一键启动

## 一键启动

### 方式一：Docker Compose（推荐）

```bash
docker compose up -d --build
```

启动后访问：

> **http://localhost:8000**

在首页打开任一项目即进入项目编辑页（`/projects/{id}`），时间轴下方依次是
「发言时长」「接话关系」与「引语检索」面板，顶部操作区有「📦 摘录包」入口
（`/projects/{id}/excerpts`，即 **http://localhost:8000/projects/{id}/excerpts**）、
「🛡️ 公开版转写」入口（`/projects/{id}/public`，即
**http://localhost:8000/projects/{id}/public**）与「🧭 覆盖盲区」入口
（`/projects/{id}/coverage`，即
**http://localhost:8000/projects/{id}/coverage**，首页项目卡片上也有
「覆盖盲区」入口），以及「📝 错词校正」入口（`/projects/{id}/corrections`，
即 **http://localhost:8000/projects/{id}/corrections**）；
更换访问端口只需调整 Compose / `-p` 端口映射（容器内固定监听 8000）。

停止：

```bash
docker compose down
```

### 方式二：Docker 原生命令

```bash
docker build -t interview-annotator .
docker run -d --name interview-annotator \
  -p 8000:8000 \
  -v "$PWD/data:/data" \
  interview-annotator
```

访问 **http://localhost:8000**。

SQLite 数据库文件位于容器内 `/data/annotation.db`，通过宿主机 `./data`
目录持久化，删除容器不丢数据。更换端口可改 `-p` 映射（容器内固定监听 8000）。

健康检查：`GET http://localhost:8000/api/health`。

## 使用流程

### 1. 导入转写稿

在首页点击「导入转写稿新建…」，或在项目内点击「导入转写」（项目内导入会替换
片段但**保留已有校注**）。两种入口共用同一套解析，支持三类格式：

**标准 SRT / WebVTT 字幕块**（`.srt` / `.vtt`）：每个字幕块由（可省略的）
块序号或 cue 标识、时间行和其后的一行或多行正文组成；块序号与 WebVTT
文件头（`WEBVTT`、`NOTE`、`STYLE`、`REGION`）会被忽略，时间行后的全部
正文行按顺序并入同一个片段，显式起止时间与块顺序原样保留。

```text
1
00:00:00,000 --> 00:00:04,000
访谈者: 感谢您今天接受访谈，能先简单介绍一下自己吗？

2
00:00:04,500 --> 00:00:15,000
受访者: 好的。我叫李明，在一家制造企业工作了二十多年，
主要负责车间的生产调度。
```

```text
WEBVTT

NOTE 说明文字不会被导入

00:00:00.000 --> 00:00:04.000
<v 访谈者>感谢您今天接受访谈，能先简单介绍一下自己吗？</v>

00:00:04.500 --> 00:00:15.000 align:start position:0%
受访者: 好的。我叫李明，在一家制造企业工作了二十多年，
主要负责车间的生产调度。
```

正文首行的 `名字: 文本`（中英文冒号均可）识别为说话人；其余行视为续行，
换行保留（检索与敏感词匹配时忽略空白，不受影响）。WebVTT 的
`<v 姓名>…</v>` 语音标签等价于说话人前缀，`<c>` 等样式标签会被去除，
时间行末尾的 cue 设置（`align:start position:0%`）不影响解析。示例见
[`examples/sample-transcript.srt`](examples/sample-transcript.srt)
与 [`examples/sample-transcript.vtt`](examples/sample-transcript.vtt)。

**带时间戳的纯文本**（`.txt`，或内容无法解析为 JSON 时；与字幕块可混用）：

```text
[00:00:00] 访谈者: 感谢您今天接受访谈
[00:00:19] 受访者: 我叫李明，在制造厂工作了二十多年
[00:00:34] --> [00:00:40] 受访者: 后来 2003 年改制
[01:09.5] 受访者: 最早全靠手摇车床
```

支持 `hh:mm:ss`、`mm:ss`、`mm:ss.mmm` 等时间格式；说话人通过行内的
`名字: 文本`（中英文冒号均可）识别；省略结束时间时，默认持续到下一片段开始
（最后一片段默认 1 秒）。示例见
[`examples/sample-transcript.txt`](examples/sample-transcript.txt)。

**JSON 片段数组**：

```json
[
  {"id": "seg-001", "start": 0.0, "end": 4.2,
   "speaker": "访谈者", "text": "感谢您今天接受访谈"}
]
```

未提供 `id` 时后端自动生成；也接受 `startTime/endTime/begin/stop/content`
等别名字段。

**此前导出的校注 JSON**（含 `segments` 与 `annotations`），直接还原整个项目。

示例文件见 [`examples/`](examples/)。

### 2. 时间轴校注

- 顶部时间轴显示片段（灰）与校注（彩色条）；
- **在时间轴上按住鼠标拖选区间**，弹窗中填写说话人、主题、备注；
- 点击已有校注条可再次编辑 / 删除；
- 片段的说话人与文本可直接在下方表格修改、新增或删除；
- 「保存」写入 SQLite；可随时「导出 JSON」下载完整校注文档。

### 3. 发言时长

在项目编辑页（入口：首页项目列表点击项目，地址
`/projects/{id}`，**http://localhost:8000/projects/{id}**）时间轴正下方的
「🕓 发言时长」面板，依据**当前转写片段**的半开时间区间 `[start, end)`
统计，片段表格中的任何未保存修改（说话人、新增 / 删除片段、时间变化）都会
**立即刷新**，无需先保存。

统计规则：

1. **忽略空说话人**（空串 / 纯空白）与**零长度或非法片段**
   （`end <= start`、时间非数字），时间一律换算为**毫秒**整数计算，
   页面以**秒**显示（保留毫秒精度，如 `3.25 s`）；
2. **先合并同一说话人自身重叠（含端点相接）的片段**，保证同一毫秒不会
   因片段重叠而给同一说话人重复累加；
3. 再以全部片段的起止时刻为切分点建立扫描线，每个基本区间内活动说话人
   集合恒定：
   - 只有一位说话人活动 → 计入该说话人的**独讲时长**；
   - 有多位说话人活动 → 该区间时长给**每位在场说话人各计一次同讲时长**，
     不计入任何人的独讲（N 人同讲，「按说话人累计的同讲总时长」计 N 次，
     属预期行为，面板中会注明）；
   - **全部**已知说话人同时活动 → 额外归入「全体同时发言」区间。
4. 面板展示：
   - 顶部统计条：独讲总时长、按说话人累计的同讲总时长、全体同时发言总
     时长与段数、说话人数；
   - 每位说话人一行：**独讲时长 / 同讲时长 / 合计**；
   - **同讲区间列表**：每段标注起止时间、在场说话人、人数与时长，
     全体在场的区间带「全体」标记；
   - 「全体同时发言」单独成组列出；
5. **点击任一同讲区间**即在顶部**现有时间轴**上以紫色框标出该区间并平滑
   滚动定位（与引语检索、质检定位共用同一时间轴），点击时间轴空白处或
   「取消定位」取消高亮。

### 4. 接话关系

在项目编辑页（入口：首页项目列表点击项目，地址
`/projects/{id}`，**http://localhost:8000/projects/{id}**）「🕓 发言时长」
面板下方的「🔀 接话关系」面板，依据**当前转写片段**（含未保存修改）分析
说话人之间的接话与插话，片段表格中的任何修改（说话人、起止时间、
新增 / 删除片段）都会**即时重算**，无需先保存。

判定规则（与发言时长共用同一套毫秒级扫描线）：

1. **先按毫秒半开区间 `[start, end)` 合并同一说话人自身相交或端点相接
   的片段**，再依全部片段的起止边界把时间轴划分为**独讲**（仅一人说话）、
   **同讲**（两人及以上同时说话）与**静默**（无人说话）区间；空说话人与
   零长度 / 非法片段一律忽略；
2. 对**时间上相邻且说话人不同**的两段独讲区间（中间只隔着静默或同讲），
   按过渡内容分类：
   - 中间**仅有静默**，且静默总时长**不超过面板中可设的静默阈值**（默认
     1 秒；端点直接相接视为零静默）→ 记一次**普通接话**；
   - 中间**仅有这两人同时发言**的同讲区间（至少一段，且每段的参与者
     恰好就是这两位说话人）→ 记一次**插话**；
   - 中间**出现第三人**（任一同讲区间包含其他说话人）或**静默与同讲
     混合**过渡 → 不计入任何一类；
3. 面板顶部可调整**静默阈值**（秒），修改后立即重算；统计条展示普通
   接话次数、插话次数与涉及的有向说话人对数；
4. 结果按**有向说话人对**（`甲 → 乙` 与 `乙 → 甲` 分开统计）逐对列出
   两类次数与**每一次的起止时间**（普通接话标注静默时长，插话标注同讲
   时长）；**点击任一时间记录**即在顶部现有时间轴上以橙色框标出该过渡
   区间并平滑滚动定位（与发言时长、引语检索、质检定位共用同一时间轴），
   点击时间轴空白处或「取消定位」取消高亮。

### 5. 引语检索

在项目编辑页（入口：首页项目列表点击项目，地址
`/projects/{id}`，**http://localhost:8000/projects/{id}**）时间轴下方的
「引语检索」面板：

1. 在输入框填写要找的**引语短语**，可在下拉框选择**说话人**（可选，精确
   匹配），需要时勾选「区分大小写」，点击「🔍 检索」（或回车）；
2. 检索规则：
   - **忽略空白**：查询串与片段文本中的所有空白字符（空格、制表、换行等）
     都不参与匹配，`后来 2003 年` 可命中查询 `后来2003年`；
   - 命中可**跨越多个片段**，但后端只拼接在时间顺序上**时间相接**
     （上一片段 `end` = 下一片段 `start`）且**说话人相同（非空）**的片段；
     片段间有空隙 / 重叠、中间夹着别的片段或说话人切换时，匹配链断开，
     **不会把跨说话人的文字误判为一句引语**；
   - 每个匹配字符都保留到原片段、原字符下标的映射，结果按片段给出逐字
     区间，原文中的命中字符以黄色高亮逐字标出；
3. 每条结果展示**说话人、覆盖的时间区间与片段数**，并按片段分行显示
   时间与高亮原文；**点击结果**即在顶部时间轴以绿色框标出该时间区间并
   平滑滚动定位（点击时间轴空白处或「取消定位」取消）；
4. 检索直接读取编辑页当前文档（**含未保存修改**，无需先保存）；
   **空查询（或纯空白）不执行检索**。

### 6. 规则批量标注

在项目内点击「⚙️ 规则批量标注」（项目列表卡片上也有「规则标注」入口）进入
规则管理页。一条规则由**命中条件**和**生成内容**组成：

| 部分 | 字段 | 说明 |
| --- | --- | --- |
| 命中条件 | 说话人 | 与片段说话人**精确相等**；留空表示不限 |
| 命中条件 | 关键词 / 正则 | 片段文本包含关键词，或匹配 Python 正则；也可选「不限制文本」 |
| 命中条件 | 区分大小写 | 关键词与正则均可配置 |
| 命中条件 | 最短持续时间 | 片段 `end - start` 小于该秒数时不命中 |
| 生成内容 | 主题 | 写入校注的主题（支持模板占位符） |
| 生成内容 | 备注模板 | 写入校注的备注，支持 `{speaker}`、`{keyword}`、`{text}`、`{segments}` |

时间轴上**相邻（连续）的命中片段会合并成一个区间**，区间从首个命中片段的
开始时间延伸到最后一个命中片段的结束时间。

使用流程：

1. 「＋ 新建规则」填写条件后点击「🔍 预览命中」：下方迷你时间轴会叠加显示
   转写片段（灰）、手工校注（红）、其他规则生成的校注（灰蓝）以及本规则
   **拟生成 / 更新的区间（虚线高亮）**，并逐条列出命中的片段原文、区间和
   将生成的主题 / 备注；统计区显示新建、更新、失效移除、手工保留的数量。
2. 保存规则后，可在规则卡片上随时「预览」，确认无误后点击「应用到时间轴」
   或预览面板中的「确认批量写入」。
3. **再次运行同一规则**时，只替换该规则自己生成的校注（以内部
   `ruleId + ruleSlot` 标识归属）：
   - 手工新建的校注、其他规则的结果一律不动；
   - 手工**编辑过**的规则校注会自动解链为手工校注，重跑不会覆盖它（规则
     会为该位置另生成一条新区间）；
   - 手工**删除**的规则校注重跑时不会复活（撤销删除后再应用除外）。
4. 页面底部「应用记录」表可**撤销本次应用**：移除该次生成 / 更新的校注并
   恢复该规则此前的结果，手工标注不受影响；被更新的应用撤销后才会回到
   可撤销状态（新应用会取代旧记录）。
5. 删除规则只会删除规则本身，其已生成的校注会**转为普通手工校注**保留。

规则与应用记录均持久化在 SQLite 中；导出的校注 JSON 里，规则生成的校注带
`source: "rule"`、`ruleId`、`ruleSlot`、`ruleName` 溯源字段（不影响普通
JSON 消费方）。重新导入导出的 JSON 时，这些校注按普通校注处理。

### 7. 双人离线编辑与三方合并（核心）

1. 在基准项目中分别点击「导出 A 离线副本」「导出 B 离线副本」，得到两份 JSON；
   （也可以直接复制项目给两位校注者，只要改动基于同一份基准。）
2. 两人各自在**新建项目时导入自己的离线副本 JSON**，独立完成校注并保存；
   或直接编辑副本文件中的 `document`。
3. 打开顶部「**三方合并**」页：
   - 基准（Base）：下拉选择原始项目，或选择基准 JSON；
   - A、B：分别选择两人的离线副本文件；
   - 点击「开始三方合并」。
4. 页面展示：
   - **自动合并的互不重叠改动**（新增 / 修改 / 删除），按片段与校注分别统计；
   - **需要逐项裁决的冲突**，每张卡片并排显示基准、A、B 三个版本。
5. 裁决方式（可混合使用）：
   - 整条采用 A / 采用 B / 丢弃；
   - 区间重叠冲突还可「双方都保留」；
   - 「按字段逐项裁决」：仅对双方改得不一致的字段选 A 或 B，其余字段自动并入；
   - 「自定义合并值 ✏️」：手工编辑合并后的最终内容。
6. 全部裁决后：
   - 「导出裁决结果 JSON」下载合并文档；
   - 「另存为新项目」；
   - 若基准来自下拉选择的项目，可「写回基准项目」。

> 未裁决完的冲突条目不会进入合并文档（页面会明确提示），裁决可反复调整、
> 实时预览，且不会改动原始项目，直到选择写回 / 另存。

### 8. 校注质检

在项目编辑页点击「🧪 校注质检」进入质检工作台（路由
`/projects/{id}/quality`），也可在质检结果中随时返回编辑页处理。

**检测方式**：后端按项目文档（或指定的时间区间）的所有片段 / 校注端点
建立**扫描线**，逐段统计同一时刻活动的校注与转写片段，检测三类问题：

| 问题类型 | 判定 | 严重级别 |
| --- | --- | --- |
| 🔹 校注越界 `out_of_bounds` | 校注区间落在转写片段覆盖范围之外 | 越过转写首 / 尾边界：`error`；整体在转写之外（不可裁剪）：`error`；仅覆盖内部空隙：`info` |
| 🔸 时间重叠 `overlap` | 两条校注时间区间相交（端点相接不算） | 一条包含另一条，或重叠时长 ≥ 较短条的一半：`error`；其余：`warning` |
| 🎤 说话人不一致 `speaker_mismatch` | 校注说话人与其覆盖的转写片段说话人不同 | 覆盖片段**全部**不一致：`error`；区间横跨说话人切换（部分一致）：`warning` |
| ❔ 说话人缺失 `speaker_missing` | 校注未填写说话人，但其覆盖片段有说话人 | `info` |

每条问题都带：

- 稳定的 `issueId`（如 `qc:overlap:ann-1|ann-2`，只取决于校注 id，
  与扫描次数、时间窗口无关，便于跨次比对 / 归档）；
- `severity`（`error` / `warning` / `info`）、定位区间与相关校注 id；
- **证据片段**：越界的未覆盖区间 / 可保留区间 / 转写覆盖范围、重叠区间
  与重叠秒数、说话人冲突涉及的转写片段原文与被覆盖秒数；
- `fixable` 与 `fix`：首尾越界且仍有合法覆盖部分时给出裁剪建议
  `{start, end}`。

工作台操作：

1. 顶部可填写**时间区间**（秒，留空表示整条转写），点击「🔎 开始质检」；
2. 统计条展示各级别、各类型数量与扫描线数；
3. 用**级别 / 类型筛选条**过滤问题列表；
4. 点击问题卡片的「📍 在时间轴定位」（或直接点击时间轴上的校注条），
   相关校注红框高亮、问题区间红色虚线标出，页面滚动到时间轴；
5. 对可修复的越界项点击「✂️ 一键裁剪到 … 并保存」：按建议区间裁剪校注、
   保存项目（规则生成的校注裁剪后会与规则解链，等同手工编辑），并自动
   重新质检；
6. 「在编辑页处理 →」携带 `?ann=&focusStart=&focusEnd=` 深链回到编辑页，
   编辑页时间轴自动高亮并滚动到该区间；
7. 「⬇️ 导出质检 JSON」下载含项目元数据、扫描窗口、统计与全部问题
   （证据片段、`issueId`、`fix`）的报告文件。

**扫描历史与两次扫描对比**：每次点击「开始质检」（含一键裁剪后的自动复检）
都会把**时间窗口、扫描时间、统计与问题快照**写入 SQLite，工作台底部的
「🕘 扫描历史」表按时间倒序列出该项目的全部扫描（窗口、各级别数量、
可裁剪数），点「查看快照」可只读回看任意一次扫描当时的问题明细。

勾选**两次时间窗口完全相同（开始 / 结束一致）**的扫描后点「⚖️ 对比所选」，
按稳定 `issueId` 标出并统计：

| 分类 | 判定 |
| --- | --- |
| 🆕 新增 | 只在较新的一次扫描中出现的 `issueId` |
| ✅ 已解决 | 只在较早的一次扫描中出现、较新扫描中已消失的 `issueId` |
| ➡️ 仍存在 | 两次扫描都出现的 `issueId`（附较新扫描的问题明细） |

**时间窗口不同的两次扫描明确禁止比较**：历史表中与当前勾选窗口不同的
行会标灰并提示「窗口不同」，选了两行不同窗口时对比按钮禁用并给出红色
提示；绕过前端直接调 API 同样返回 400。对比时按扫描时间自动区分
基准（旧）/ 对比（新），与两个参数的传入顺序无关。删除项目时其全部
扫描历史随外键级联一并清除。

### 10. 摘录包

在项目编辑页点击「📦 摘录包」进入摘录包页面，路由
`/projects/{id}/excerpts`，访问地址
**http://localhost:8000/projects/{id}/excerpts**（端口随 Compose /
`-p` 映射调整，容器内固定 8000）。摘录包是**只读导出**，不会修改原项目。

1. **输入多段起止时间**（秒）：行数不限，**顺序不限、允许重叠**；
   结束时间必须晚于开始时间，不能为负数，否则无法预览（绕过前端直接调
   API 同样返回 400 / 422）。
2. **预览时合并区间**：相交或**首尾相接**的输入区间自动合并成若干互不
   相连的合并区间，预览会标明每个合并区间由哪些输入区间合并而来。
3. **转写片段只收录完整落在合并区间内的**（半开区间 `[start, end)`）；
   与区间时间相交但跨界的片段（起于区间前、终于区间后，或两侧都伸出）
   **整段列为排除项**，只在「排除项」中带原因展示，**不会截取片段的
   一部分文本充作摘录**。同一片段跨越多个不相连合并区间时，在汇总区
   去重为一条，标注「跨越区间之间的空隙」及涉及的区间序号。
4. **校注按边界裁剪**：与合并区间时间相交的校注裁剪为交集区间（仅端点
   相接不算相交），保留原校注的全部字段（说话人、主题、备注、规则溯源
   等）；一条校注跨越多个不相连合并区间时**拆成多条**（`sourcePart` /
   `sourcePartCount` 标明第几部分），每条都带
   `sourceAnnotationId`（**原校注 ID**）作为来源标识；摘录包内校注 ID
   形如 `exc-{原ID}` / `exc-{原ID}-{序号}`。
5. **预览展示**：每个合并区间单独成卡，列出收录片段、裁剪后校注（含
   来源标识与拆分标记）的数量与明细、排除片段及跨界原因；顶部统计输入
   区间数、合并后区间数、收录片段 / 校注数、排除片段数与被拆分的校注
   来源数，底部另有去重后的排除片段汇总。修改区间行后预览标记为过期，
   需重新生成预览才能下载。
6. **确认后下载 JSON**：「⬇️ 确认并下载摘录包 JSON」返回附件形式的
   JSON（文件名 `{项目名}-摘录包.json`），内含项目标识、合并区间
   （含合并来源、收录片段、裁剪校注、区间内排除项）、去重排除项汇总
   与统计信息；服务端不写库，**原项目保持不变**。

### 11. 公开版转写

在项目编辑页点击「🛡️ 公开版转写」进入公开版转写页面，路由
`/projects/{id}/public`，访问地址
**http://localhost:8000/projects/{id}/public**（端口随 Compose /
`-p` 映射调整，容器内固定 8000）。公开版转写是**只读导出**，基于
**当前已保存**的转写（编辑页未保存的修改不包含在内），不会修改原项目。

1. **输入多条敏感词**：行数不限，空白行自动忽略；可勾选「区分大小写」
   （默认不区分）。匹配**忽略空白**——敏感词与片段文本中的所有空白字符
   都不参与匹配，`后来 2003 年` 可被敏感词 `后来2003年` 命中；命中可
   **跨越多个时间相接**（上一片段 `end` = 下一片段 `start`）**且说话人
   相同（非空）的片段**，片段间有空隙、重叠或说话人切换时匹配链断开，
   不会把跨说话人的文字连成一次命中。
2. **遮盖规则**：每次命中的**非空白字符**按原字符位置替换为方块 `■`，
   原文空白原样保留（文本长度与排版不变）；不同敏感词（或同一敏感词的
   不同出现位置）的命中重叠时，同一字符**只遮盖一次**。片段 ID、起止
   时间与分段划分全部保留。
3. **选择需匿名的说话人**：点击「现有说话人」名称或手动输入添加；选中
   的说话人在公开版中替换为 `说话人 1`、`说话人 2`……编号按其在已保存
   转写中**首次出现的顺序**分配（选中但未出现的名称按输入顺序递补），
   **预览与下载使用同一份编号**；未选中的说话人名称原样保留。
4. **预览**：统计条展示片段数、敏感词命中次数、遮盖字符数、被遮盖片段数
   与匿名说话人 / 片段数；下方列出每个敏感词的命中次数、原说话人 →
   匿名编号对照表，以及完整公开版片段（被遮盖字符黄色高亮、匿名说话人
   标注原名称）。修改输入后预览标记为过期，需重新生成预览才能下载。
5. **确认后下载 JSON**：「⬇️ 确认并下载公开版 JSON」返回附件形式的
   JSON（文件名 `{项目名}-公开版转写.json`），**只含转写片段**——每个
   片段只有 `id`、`start`、`end`、`speaker`（匿名后）、`text`（遮盖后）
   五个字段；不含校注、原说话人姓名与敏感词原文，服务端不写库，
   **原项目保持不变**。

### 12. 校注覆盖盲区

在项目编辑页点击「🧭 覆盖盲区」（首页项目卡片上也有「覆盖盲区」入口）
进入覆盖盲区工作台，路由 `/projects/{id}/coverage`，访问地址
**http://localhost:8000/projects/{id}/coverage**（端口随 Compose /
`-p` 映射调整，容器内固定 8000）。工作台是**只读**的，基于**已保存**
的转写片段与校注统计（编辑页未保存的修改不包含在内），不会修改原项目。

统计规则（半开时间区间，毫秒精度，页面以秒显示）：

1. **忽略空说话人**（空串 / 纯空白）与**零长度或非法片段 / 校注**
   （`end <= start`、时间非数字）；
2. **先合并同一说话人自身重叠（含端点相接）的发言片段**，保证同一毫秒
   不会因片段重叠而给同一说话人重复累加；
3. **仅同名说话人的校注可覆盖其发言**：把该说话人的全部校注先做并集
   （**重叠校注不重复计时**），再与其发言区间取交集——校注**超出发言
   范围的部分**（越出转写、覆盖内部空隙、延伸到他人发言的部分）一律
   **不计入**覆盖；
4. 发言区间减去同名校注的覆盖并集，余下的即该说话人的**未覆盖盲区**；
   **多人同时发言分别计入各自说话人**（A 发言的覆盖情况只看 A 的校注，
   与 B 是否在场、是否有校注无关）。

工作台展示：

1. 顶部统计条：说话人数、实际发言总时长、已覆盖总时长、总覆盖率与
   未覆盖总时长（含盲区段数，各说话人时长之和，多人同讲区间会计入
   每位在场说话人）；
2. **说话人筛选条**：「全部」与每位说话人一个按钮（按钮上直接显示该
   说话人覆盖率与盲区段数），点击即按说话人筛选盲区列表与统计表；
3. **按说话人统计表**：每行列出实际发言时长、已覆盖时长、未覆盖时长、
   覆盖率（带进度条）与盲区段数，点击说话人名同样可筛选；
4. **未覆盖发言区间列表**：每段标注起止时间、说话人与未覆盖时长；
   **点击任一行**即携带 `?focusStart=&focusEnd=&focusSource=coverage`
   **深链返回编辑页**，时间轴以琥珀色框标出该盲区并平滑滚动定位，
   可在时间轴上直接拖选补全校注（提示条可「取消定位」或返回盲区
   工作台）；项目不存在时 API 与页面返回 **404**。

### 13. 转写错词批量校正

在项目编辑页点击「📝 错词校正」进入错词校正工作台，路由
`/projects/{id}/corrections`，访问地址
**http://localhost:8000/projects/{id}/corrections**（端口随 Compose /
`-p` 映射调整，容器内固定 8000）。校正基于**已保存**的转写（编辑页
未保存的修改不包含在内），只改写命中片段的文本，其余内容一律不动。

1. **填写校正词表**：每行一组「错词 → 正词」，行数不限；正词留空表示
   **删除**该错词，完全空白的行会被忽略。**错词留空的行与重复配置的
   错词**会在页面即时标错并禁用预览按钮，绕过前端直接调 API 同样返回
   400。
2. **预览校正**：点击「🔍 预览校正」，后端对**已保存**的转写逐片段
   匹配——每个片段从左到右**只扫描原文一次**，同一位置**优先最长
   错词**（如同时配置「的」与「的候」，原文「的候」整体替换为「时候」），
   **替换出的文字不再参与匹配**（正词中即使含有别的错词也不会被二次
   替换，错词也绝不跨片段匹配）。统计条显示校正组数、命中片段数、
   **影响片段数**与替换处数；下方逐片段列出原文（黄色高亮命中错词）
   与校正后文本（绿色高亮替换出的正词）。修改词表后预览标记为过期，
   需重新生成预览才能确认。
3. **确认保存**：点击「✅ 确认校正」时，后端重新校验词表，并在写入
   事务内核对预览对应的**转写版本指纹**——若期间已保存的转写被编辑
   （任何片段字段变化）或重新导入，本次确认被拒绝（**409**）并要求
   重新预览，不会写入任何内容。校验通过后在**一次事务**中保存改动
   的片段文本：片段 ID、起止时间、说话人及全部校注（含规则溯源字段）
   原样保留，失败整体回滚、不留部分修改。
4. **查看结果**：保存成功后工作台显示本次**影响片段数**与替换处数，
   点击「返回编辑页查看结果 →」回到项目编辑页（顶部弹出已保存提示），
   片段表、引语检索与发言时长统计立即使用校正后的文本。

### 14. 并发保存保护（文档版本）

同一项目在两个页面（两个标签页 / 两台设备）同时打开时，旧页面的整份
保存不会覆盖另一页面已确认的修改（如错词校正、说话人归一、规则应用、
重新导入）。

1. **读取带版本**：每次读取项目（`GET /api/projects/{id}`，含列表与
   所有保存响应）都附带 `documentVersion`——整份项目文档（全部片段与
   校注的所有字段）的 SHA-256 内容指纹。同一文档版本恒定；**任何**
   内容变化都会改变版本，即使两次保存落在同一秒（不依赖秒级精度的
   `updatedAt`）。
2. **保存带版本**：编辑页「保存」（`PUT /api/projects/{id}`）必须携带
   读取时的 `documentVersion`（缺失返回 **400**）；后端在**同一写入
   锁内**重新计算当前文档版本并比对，一致才写入并返回新版本。
3. **保存结果只确认本次快照**：点击保存后仍可继续修改项目名、片段与
   校注，但进行中的请求只提交点击时的快照；响应返回时前端比对编辑序号——
   若请求期间**没有新编辑**，正常清除「未保存」状态；若请求期间**又有
   编辑**，本次响应只确认已提交的那份快照：屏幕上的当前草稿与「未保存」
   标记保留（离页仍会提示），同时采用响应中的 `documentVersion` 作为新
   基准，可直接再次保存新草稿，不会把保存后的新改动误报为已保存。
4. **版本不一致（409）**：期间另一页面已保存过任何修改时，本次保存
   **任何字段都不写入**（包括项目名），返回 **409**；编辑页保留未保存
   草稿，顶部出现冲突提示条，「保存」按钮停用。保存失败（网络 / 服务端
   错误）同样不清除草稿与「未保存」标记。
5. **重新加载后才能再保存**：点击提示条上的「⟳ 重新加载最新项目」
   主动放弃本页草稿、载入最新文档与新版本后，才能继续编辑并保存。
   质检工作台的「一键裁剪并保存」同样携带版本，冲突时会提示并自动
   重新读取最新项目。

## 合并规则说明

合并以条目的稳定 `id`（片段 `seg-*`、校注 `ann-*`）在 **基准 / A / B**
三份文档中比对：

| 情形 | 结果 |
| --- | --- |
| 只有一方新增、修改、删除 | 自动采用 |
| 双方修改同一 id 且内容相同 | 自动采用 |
| 双方修改同一 id，但改动落在**不同字段** | 字段级自动合并 |
| 双方修改同一 id，且同一字段改成不同值 | **字段冲突**，逐项裁决 |
| 一方修改、另一方删除同一条 | **修改/删除冲突**，逐项裁决 |
| 双方各自新增校注，且时间区间互不重叠 | 自动并存（端点相接不算重叠） |
| 双方各自新增校注，且时间区间重叠 | **区间重叠冲突**（重叠链聚合成一个冲突组），逐项裁决 |
| 双方都删除同一条 | 自动删除 |

自定义合并值在服务端校验：时间必须为非负数字、`end >= start`、片段文本非空。

导出 / 合并的 JSON 结构：

```json
{
  "segments": [
    {"id": "seg-…", "start": 0.0, "end": 4.2,
     "speaker": "访谈者", "text": "…"}
  ],
  "annotations": [
    {"id": "ann-…", "start": 0.0, "end": 18.5,
     "speaker": "受访者", "topic": "个人背景", "note": "…"}
  ]
}
```

离线副本文件在文档之外附带 `baseProjectId / editor / exportedAt` 元数据，
合并页能直接识别其 `document`。

### `GET /api/projects/{id}` 与 `PUT /api/projects/{id}`（文档版本）

读取项目（含项目列表、保存响应与导入响应）返回的 JSON 都带有
`documentVersion`——整份项目文档（`segments` 与 `annotations` 的所有
字段）的 SHA-256 内容指纹，同一文档版本恒定，任何内容变化都会改变它
（与秒级精度的 `updatedAt` 无关，同秒更新也能区分）：

```json
{
  "id": "proj-…",
  "name": "访谈A",
  "document": { "segments": [], "annotations": [] },
  "documentVersion": "9f2c…",
  "createdAt": "…",
  "updatedAt": "…"
}
```

保存文档必须携带读取时的版本：

```json
{
  "name": "访谈A",
  "document": { "segments": [], "annotations": [] },
  "documentVersion": "9f2c…（取读取时的返回值）"
}
```

- 后端在**同一写入锁内**重新计算已存文档的版本并比对，一致才写入，
  响应携带新版本；内容未变化的重复保存版本不变（不会误判冲突）；
- `documentVersion` 缺失 → **400**（`缺少文档版本，请重新加载项目后再保存`）；
- 版本不一致（期间另一页面已保存）→ **409**
  （`项目文档在此期间已被其他页面修改…请重新加载最新项目后再保存`），
  **任何字段都不写入**（含项目名），需重新 `GET` 取最新文档与版本后再
  保存；项目不存在 → **404**。

### `POST /api/projects/{id}/quote-search`

引语检索。请求体：

```json
{
  "query": "后来2003年厂子改制",
  "speaker": "受访者",
  "caseSensitive": false,
  "document": { "segments": [], "annotations": [] }
}
```

- `query` 必填；**空串或纯空白返回 400，不执行检索**；
- `speaker` 可选，留空表示不限说话人，否则要求与片段说话人精确相等；
- `caseSensitive` 默认 `false`（大小写不敏感）；
- `document` 可选，传入时检索该文档（前端用于携带编辑页**未保存**的
  当前内容），省略时检索已保存的项目文档；
- 匹配忽略所有 Unicode 空白；只拼接时间相接且同说话人的片段链，
  跨说话人 / 有空隙 / 重叠的片段不会相连。

返回（每个 match 的 `segments[].ranges` 为命中字符在该片段原文中的
半开区间，空白字符不包含在区间内，可据此逐字高亮）：

```json
{
  "projectId": "proj-…",
  "projectName": "访谈A",
  "query": "后来2003年厂子改制",
  "speaker": "受访者",
  "count": 1,
  "matches": [
    {
      "start": 0.0, "end": 9.0, "speaker": "受访者",
      "matchedText": "后来2003年厂子改制", "segmentCount": 2,
      "segments": [
        {"id": "seg-001", "start": 0.0, "end": 4.5,
         "speaker": "受访者", "text": "后来 2003 年",
         "matchStart": 0, "matchEnd": 8,
         "ranges": [[0, 2], [3, 7], [7, 8]]},
        {"id": "seg-002", "start": 4.5, "end": 9.0,
         "speaker": "受访者", "text": "厂子改制",
         "matchStart": 0, "matchEnd": 4, "ranges": [[0, 4]]}
      ]
    }
  ]
}
```

`start` / `end` 为命中覆盖的首个片段开始时间与末个片段结束时间。
项目不存在返回 404。

### `POST /api/projects/{id}/speaker-rename/preview` 与 `…/speaker-rename`

说话人归一。两个端点接收相同的请求体——一组旧名 → 目标名映射：

```json
{
  "mappings": [
    { "from": "李明", "to": "老李" },
    { "from": "老李", "to": "李" }
  ]
}
```

- 名称比较忽略首尾空白；纯空白说话人视为未填写，永不参与归一；
- **链式映射归并**：上例中 `李明`、`老李` 的最终去向都是 `李`；
- 校验失败返回 **400**：目标名为空、旧名为空（整行空白除外）、同一旧名
  多条映射、循环映射（含 `A → A` 自映射与 `A → B → A` 间接循环）。

`preview` 只读不落库，汇总已保存的转写片段、校注与规则（精确说话人
条件）三处来源的现有名称，返回每个名称的最终去向与影响数量：

```json
{
  "projectId": "proj-…",
  "projectName": "访谈A",
  "names": [
    { "name": "李明", "final": "李", "changed": true,
      "segments": 1, "annotations": 1, "rules": 0, "total": 2 },
    { "name": "王主任", "final": "王主任", "changed": false,
      "segments": 1, "annotations": 1, "rules": 0, "total": 2 }
  ],
  "mappings": [
    { "from": "李明", "to": "老李", "final": "李",
      "chain": ["李明", "老李", "李"] }
  ],
  "summary": { "speakers": 3, "renamed": 2,
               "segments": 2, "annotations": 1, "rules": 2 }
}
```

`speaker-rename`（提交）先做一次同样的校验与链式归并，然后在**一次
事务**中改写三处说话人字段：项目文档里的片段与校注（仅 `speaker`
字段，记录 ID 与时间、文本、主题、备注、规则溯源等其余内容原样保留）、
以及该项目全部规则的说话人条件；任一环节失败整体回滚，不留部分修改。
返回更新后的项目、实际改写数量与归并后的映射：

```json
{
  "project": { "id": "proj-…", "document": { "…": "…" } },
  "counts": { "segments": 2, "annotations": 1, "rules": 2 },
  "renamed": [
    { "from": "李明", "to": "老李", "final": "李",
      "chain": ["李明", "老李", "李"] }
  ]
}
```

项目不存在返回 404。

### `POST /api/projects/{id}/excerpts/preview` 与 `…/excerpts/download`

摘录包。两个端点请求体相同，`download` 额外以
`Content-Disposition: attachment`（文件名 `{项目名}-摘录包.json`）返回
同一份 JSON；两者都**只读、不写库**，原项目文档不会被修改：

```json
{
  "ranges": [
    { "start": 30.0, "end": 90.0 },
    { "start": 0.0, "end": 20.0 }
  ]
}
```

- 区间顺序不限、允许重叠；相交或首尾相接（端点相等）的区间会合并；
- 校验失败：空区间列表、非数字为 **422**；`end <= start` 为 **400**；
  负数为 **422**；项目不存在为 **404**。

返回（片段仅收录完整落在合并区间内的；跨界片段只出现在排除项中，
文本保持整段原文；校注按边界裁剪，跨多个不相连区间时拆分并保留
`sourceAnnotationId`）：

```json
{
  "projectId": "proj-…",
  "projectName": "访谈A",
  "summary": {"inputRangeCount": 2, "mergedRangeCount": 2,
              "segmentCount": 3, "annotationCount": 3,
              "excludedSegmentCount": 1, "splitAnnotationCount": 1},
  "intervals": [
    {
      "index": 0, "start": 0.0, "end": 20.0,
      "sources": [{"start": 0.0, "end": 20.0}],
      "segments": [{"id": "seg-1", "start": 0.0, "end": 10.0,
                    "speaker": "访谈者", "text": "…"}],
      "segmentCount": 2,
      "annotations": [
        {"id": "exc-ann-1-1", "start": 15.0, "end": 20.0,
         "speaker": "受访者", "topic": "…", "note": "…",
         "sourceAnnotationId": "ann-1",
         "sourcePart": 1, "sourcePartCount": 2}
      ],
      "annotationCount": 1,
      "excludedSegments": [
        {"id": "seg-3", "start": 18.0, "end": 40.0, "text": "…",
         "reason": "crosses_end"}
      ],
      "excludedSegmentCount": 1
    }
  ],
  "excludedSegments": [
    {"id": "seg-3", "start": 18.0, "end": 40.0, "text": "…",
     "intervalIndices": [0, 1], "reason": "crosses_gap"}
  ]
}
```

排除原因 `reason`：`crosses_start`（片段起于区间开始之前）、
`crosses_end`（片段终于区间结束之后）、`crosses_both`（两侧都伸出）、
`crosses_gap`（跨界多个不相连合并区间，仅出现在去重汇总中）。

### `POST /api/projects/{id}/public-transcript/preview` 与 `…/public-transcript/download`

公开版转写。两个端点请求体相同，始终作用于**已保存**的项目文档（只读、
不写库）；`download` 额外以 `Content-Disposition: attachment`（文件名
`{项目名}-公开版转写.json`）返回**只含片段**的公开版 JSON：

```json
{
  "sensitiveWords": ["后来改制", "李明"],
  "anonymizeSpeakers": ["李明", "王主任"],
  "caseSensitive": false
}
```

- `sensitiveWords`：多条敏感词；匹配忽略所有 Unicode 空白（词内空白同样
  忽略），可跨时间相接、说话人相同（非空）的片段，遇空隙 / 重叠 / 换人
  即断开；空白行与重复词自动忽略；
- `anonymizeSpeakers`：需匿名的说话人（精确名称，忽略首尾空白）；匿名
  编号 `说话人 1`、`说话人 2`……按其在已保存转写中首次出现的顺序分配，
  预览与下载一致；
- `caseSensitive` 默认 `false`；
- 列表类型错误为 **422**；项目不存在为 **404**。

`preview` 返回（每个片段带 `maskedRanges` 半开字符区间供逐字高亮，
`speakers` 给出原名称 → 匿名编号对照与涉及片段数）：

```json
{
  "projectId": "proj-…",
  "projectName": "访谈A",
  "generatedAt": "2026-09-24T10:00:00+00:00",
  "sensitiveWords": ["后来改制"],
  "words": [{"word": "后来改制", "count": 2}],
  "speakers": [
    {"original": "李明", "alias": "说话人 1",
     "segmentCount": 3, "appears": true}
  ],
  "summary": {"segmentCount": 5, "hitCount": 2, "maskedSegmentCount": 2,
              "maskedCharCount": 8, "anonymizedSpeakerCount": 1,
              "anonymizedSegmentCount": 3},
  "segments": [
    {"id": "seg-1", "start": 0.0, "end": 4.5, "speaker": "说话人 1",
     "text": "■■■■，当时", "masked": true, "maskedChars": 4,
     "maskedRanges": [[0, 4]], "anonymized": true}
  ]
}
```

`download` 的响应体只含公开字段——每个片段仅 `id`、`start`、`end`、
`speaker`（匿名后）、`text`（遮盖后），不含校注、原说话人姓名与敏感词
原文：

```json
{
  "kind": "public-transcript",
  "projectId": "proj-…",
  "projectName": "访谈A",
  "generatedAt": "2026-09-24T10:00:00+00:00",
  "segmentCount": 5,
  "segments": [
    {"id": "seg-1", "start": 0.0, "end": 4.5,
     "speaker": "说话人 1", "text": "■■■■，当时"}
  ]

```

### `GET /api/projects/{id}/coverage`

校注覆盖盲区。基于**已保存**的项目文档（只读、不写库），可加查询参数
`speaker`（精确、自动去除首尾空白）只返回某一位说话人；未知说话人是
合法的空报告（`speakers: []`），**项目不存在返回 404**。

统计按毫秒整数半开区间进行：忽略空说话人与零长度 / 非法条目；同一
说话人自身重叠或相接的发言片段先合并；仅同名说话人的校注可覆盖其
发言（校注先并集，重叠不重复计时，再裁剪到发言范围内，超出发言的
部分不计入）；多人同时发言分别计入各自说话人。

```json
{
  "projectId": "proj-…",
  "projectName": "访谈A",
  "speaker": null,
  "summary": {
    "speakers": 2,
    "speechMs": 55000, "speechSeconds": 55.0,
    "coveredMs": 33000, "coveredSeconds": 33.0,
    "uncoveredMs": 22000, "uncoveredSeconds": 22.0,
    "coverage": 0.6,
    "uncoveredIntervalCount": 3
  },
  "speakers": [
    {
      "speaker": "甲",
      "speechMs": 30000, "speechSeconds": 30.0,
      "coveredMs": 30000, "coveredSeconds": 30.0,
      "uncoveredMs": 0, "uncoveredSeconds": 0.0,
      "coverage": 1.0,
      "speechRanges": [{"start": 0.0, "end": 20.0},
                       {"start": 50.0, "end": 60.0}],
      "uncoveredCount": 0,
      "uncoveredRanges": []
    },
    {
      "speaker": "乙",
      "speechMs": 25000, "speechSeconds": 25.0,
      "coveredMs": 3000, "coveredSeconds": 3.0,
      "uncoveredMs": 22000, "uncoveredSeconds": 22.0,
      "coverage": 0.12,
      "speechRanges": [{"start": 30.0, "end": 45.0},
                       {"start": 55.0, "end": 65.0}],
      "uncoveredCount": 3,
      "uncoveredRanges": [
        {"start": 30.0, "end": 35.0,

```

`coverage` 为 `coveredMs / speechMs`（保留四位小数，无发言时为 `0.0`）；
`uncoveredRanges` 即发言区间减去同名校注覆盖并集后的盲区，按时间顺序
排列，前端点击盲区深链 `?focusStart=&focusEnd=&focusSource=coverage`
回到编辑页定位。

### `POST /api/projects/{id}/corrections/preview` 与 `…/corrections/apply`

转写错词批量校正。`preview` 只读、不写库，基于**已保存**的转写逐片段
预览命中与校正后文本；`apply` 确认预览并在**一次事务**中保存改动的
片段文本（片段 ID、起止时间、说话人及全部校注原样保留）。两个端点
接收相同的词表，`apply` 额外要求带回预览返回的转写版本：

```json
{
  "pairs": [
    { "from": "的候", "to": "时候" },
    { "from": "的", "to": "得" }
  ],
  "transcriptVersion": "9f2c…（仅 apply 需要，取预览返回值）"
}
```

- 匹配规则：逐片段独立、从左到右**只扫描原文一次**；同一位置**优先
  最长错词**；替换出的文字不再参与匹配；正词为空表示删除该错词；
- 词表校验（两端点一致）：错词为空的行、重复错词 → **400**；
- `preview` 返回 `transcriptVersion`（已保存转写片段的 SHA-256 指纹，
  任何片段字段变化都会改变它）、每组词的命中次数、命中片段的原文 /
  校正后文本与逐处命中位置，以及汇总统计（含 `changedSegmentCount`
  影响片段数）；
- `apply` 在写入事务内重新校验词表并核对 `transcriptVersion`：缺失
  → **400**；与当前已保存转写不一致（期间被编辑或重新导入）→
  **409**（`已保存的转写在此期间被编辑或重新导入，请重新生成预览后
  再确认`），不写任何内容；项目不存在 → **404**。

`preview` 返回（`segments` 只列出有命中的片段，`hits` 为原文中的
半开字符区间）：

```json
{
  "projectId": "proj-…",
  "projectName": "访谈A",
  "transcriptVersion": "9f2c…",
  "pairs": [{"from": "的候", "to": "时候"}],
  "words": [{"from": "的候", "to": "时候", "count": 1}],
  "segments": [
    {"id": "seg-1", "start": 0.0, "end": 4.5, "speaker": "受访者",
     "originalText": "等的候人很多", "correctedText": "等时候人很多",
     "changed": true, "hitCount": 1,
     "hits": [{"from": "的候", "to": "时候", "start": 1, "end": 3}]}
  ],
  "summary": {"segmentCount": 5, "pairCount": 1, "hitSegmentCount": 1,
              "changedSegmentCount": 1, "hitCount": 1}
}
```

`apply` 成功时返回更新后的项目、影响数量与改动的片段 ID：

```json
{
  "project": { "id": "proj-…", "document": { "…": "…" } },
  "counts": { "segments": 1, "replacements": 1 },
  "changedSegmentIds": ["seg-1"]
}
```

### `POST /api/projects/{id}/quality-check`

对**已保存**的项目文档做质检。请求体可省略（或为 `{}`），表示整条转写；
也可指定扫描时间窗口：

```json
{ "start": 60.0, "end": 300.0 }
```

窗口非法（`end <= start`）返回 400，`start` 为负返回 422。返回：

```json
{
  "projectId": "proj-…",
  "projectName": "访谈A",
  "window": { "start": 0.0, "end": 412.5 },
  "explicitWindow": false,
  "summary": {
    "total": 3, "error": 2, "warning": 0, "info": 1,
    "outOfBounds": 1, "overlap": 1,
    "speakerMismatch": 1, "speakerMissing": 0,
    "annotations": 8, "segments": 42,
    "scanLines": 37, "fixable": 1
  },
  "issues": [
    {
      "issueId": "qc:out_of_bounds:ann-1",
      "type": "out_of_bounds",
      "severity": "error",
      "start": 300.0, "end": 412.5,
      "message": "校注「企业改制」越出转写边界：…可裁剪到 300.0s–405.0s",
      "annotationId": "ann-1",
      "annotationIds": ["ann-1"],
      "annotations": [{ "id": "ann-1", "start": 300.0, "end": 412.5,
                       "speaker": "受访者", "topic": "企业改制" }],
      "evidence": {
        "uncoveredRanges": [{ "start": 405.0, "end": 412.5 }],
        "coveredRanges": [{ "start": 300.0, "end": 405.0 }],
        "transcriptCoverage": { "start": 0.0, "end": 405.0 }
      },
      "fixable": true,
      "fix": { "start": 300.0, "end": 405.0 }
    }
  ]
}
```

`type` 为 `overlap` 时 `evidence` 含 `overlapSeconds` 与重叠 `ranges`，
`annotationIds` 列出冲突双方；`speaker_mismatch` / `speaker_missing` 时
`evidence` 含 `annotationSpeaker`、`segmentSpeakers` 与逐个转写片段
（含 `coveredSeconds`）。问题按严重级别（error → warning → info）再按
开始时间排序。前端的「一键裁剪」即把 `fix` 写回对应校注后调用
`PUT /api/projects/{id}` 保存（不产生额外服务端状态）。每次质检都会在
`quality_scans` 表落一条记录，响应中额外带 `scanId` 与 `scannedAt`。

### 扫描历史与对比

`GET /api/projects/{id}/quality-scans` 按时间倒序返回扫描摘要
（列表项不含 `issues` 明细）：

```json
{
  "id": "scan-ab12cd34ef56",
  "projectId": "proj-…",
  "window": { "start": 0.0, "end": 412.5 },
  "explicitWindow": false,
  "summary": { "total": 3, "error": 2, "…": "…" },
  "createdAt": "2026-09-23T10:22:36.669112+00:00"
}
```

`GET /api/projects/{id}/quality-scans/{scanId}` 在此基础上额外返回完整
`issues` 数组（与质检响应中的问题结构一致，含证据 / `fix`）。

`POST /api/projects/{id}/quality-scans/compare`：

```json
{ "scanIdA": "scan-…", "scanIdB": "scan-…" }
```

服务端按 `createdAt` 自动把较早的扫描作为基准；两次扫描必须属于该项目
且**时间窗口完全相同**（`window.start/end` 一致，容差 1e-6），否则：

- 两次窗口不同 → **400**（`两次扫描的时间窗口不同，无法比较…`）；
- 两个 id 相同 → 400；任一扫描不存在 / 不属于该项目 → 404。

同窗口时返回（问题数组按基准 / 对比各自的原有排序）：

```json
{
  "window": { "start": 0.0, "end": 412.5 },
  "base":   { "id": "scan-…", "createdAt": "…", "summary": { "…": "…" } },
  "target": { "id": "scan-…", "createdAt": "…", "summary": { "…": "…" } },
  "counts": { "new": 1, "resolved": 2, "persistent": 3 },
  "newIssues":      [ { "issueId": "qc:overlap:ann-3|ann-9", "…": "…" } ],
  "resolvedIssues": [ { "issueId": "qc:out_of_bounds:ann-1", "…": "…" } ],
  "persistentIssues": [ { "issueId": "qc:speaker_mismatch:ann-2", "…": "…" } ]
}
```
